# Decisions

Each entry: date, decision, alternatives, reason. Architectural decisions also have an ADR in `docs/adr/`.

| Date | Decision | Alternatives | Reason |
|---|---|---|---|
| 2026-10-16 | Toy targets are a uv workspace member (`examples/toy-targets`) used through the `dev` dependency group. | Separate repository; vendored module under `tests/`. | Keeps them out of the wheel while letting tests import them. |
| 2026-10-16 | Judge prompts live in `prompts/` and are force-included in the wheel as `evalgate/prompts/`. | Store prompts only inside the package. | The spec places prompts at the repository root; the installed library still needs them. |
| 2026-10-16 | Provider SDKs (`anthropic`, `openai`) are optional extras imported lazily by `evalgate.llm.gateway`. | Hard dependencies. | Keeps `import evalgate` under 300 ms and the default install offline-only. |
| 2026-10-16 | The `[langfuse]` extra is empty: the exporter uses the Langfuse public ingestion HTTP API through `httpx`. | Depend on the Langfuse SDK. | The SDK (v3+) is OTel based and harder to point at a WireMock double; the HTTP API is the stable contract. |
| 2026-10-16 | Pinned tool versions are committed in `tools/versions.env` and copied to the gitignored `.tools/versions.env` on install. | Commit `.tools/versions.env` directly. | The spec gitignores `.tools/`; a committed source of truth is needed for reproducibility. |
| 2026-10-16 | Tool versions: hadolint 2.15.1, trivy 0.76.0, shellcheck 0.11.0, actionlint 1.7.12, gitleaks 8.30.1, markdownlint-cli2 0.23.3. | `latest` at install time. | GitHub API `latest` lookups are blocked in the cloud container; these are the newest versions whose release assets were downloadable on 2026-10-16. |
| 2026-10-16 | Runtime images use `gcr.io/distroless/python3-debian13` (Python 3.13) after a `python:3.13-slim` builder. | `python:3.13-slim` runtime. | The slim runtime measured 260 MB with numpy and duckdb, over the 250 MB budget; distroless measured 202 MB, has no shell or package manager, and Appendix A prefers slim or distroless bases. |
| 2026-10-16 | The CLI uses Typer with `rich_markup_mode=None` (plain Click help). | Rich help output. | Plain output is stable for golden tests and CI logs. |
| 2026-10-16 | Relative `dataset` paths in a suite resolve against the working directory first, then the suite's folder. | Suite-relative only. | The spec's examples use repository-root paths (`evals/datasets/...`); suite-relative paths keep imported suites portable. |
| 2026-10-16 | Suites may list `plugins` (modules imported before the run) and custom metrics name their implementation in `params.metric`. | Entry points. | Explicit, offline and easy to read in a suite file. |
| 2026-10-16 | Label rows name their rubric; `evalgate calibrate` scores only the rows of the rubric it is given. The 80 test items of `answer_correctness.labels.v1.jsonl` split into 64 pointwise (answer_correctness) and 16 pairwise (pairwise_preference) items; `make calibrate` covers both. | One rubric judging both shapes. | A pairwise item needs a pairwise prompt; keeping one rubric per shape keeps the prompts honest and comparable. |
| 2026-10-16 | `rubric_adherence` (likert5) gets its own 60-item label file (`rubric_adherence.labels.v1.jsonl`), with binary labels (adherent = rating 5). | Leave the likert rubric uncalibrated. | `make calibrate` must calibrate every rubric, and a judge is adopted only after calibration. |
| 2026-10-16 | Pointwise position swap renders the reference before and after the candidate; a verdict that changes with the order is `position_inconsistent` (score 0.5). | Position swap only for pairwise rubrics. | Order effects exist in pointwise prompts too, and it makes the position-inconsistency threshold meaningful for every rubric. |
| 2026-10-16 | Calibration adds `--split` (default `test`) so rubric work iterates on `dev`. | Test only. | Never tune on `test`. |
| 2026-10-16 | The response cache keeps offline (rules, cassettes) and live verdicts apart, and treats a row whose `request_digest` differs as stale. | One shared namespace. | An offline report must not depend on live verdicts in a local cache (NFR-9), and a prompt edited without a version bump must not serve stale verdicts. |
| 2026-10-16 | `gate_audit` retention records the last pruned row in `audit_anchor` (migration 002); verification continues the chain from that anchor. | Trust the oldest kept row. | Deleting head rows outside `evalgate gc` must be detected. |
| 2026-10-16 | A live run refuses a judge model with no price in `pricing.yaml` (exit 3, before any call). | Price it at 0. | An unpriced model would silently disable `LIVE_EVAL_BUDGET_USD`. |
| 2026-10-16 | The `[ragas]` extra pins `langchain-community<0.4` and adds `rapidfuzz`. | Unpinned. | ragas 0.4.3 imports `langchain_community.chat_models.vertexai`, removed in 0.4; its string metrics need rapidfuzz. |
| 2026-10-16 | Imported Promptfoo `llm-rubric` asserts become ungated judge metrics with a generated rubric. | Gated judge. | A judge is adopted only after calibration; an imported rubric has no labels yet. |
| 2026-10-16 | Baselines `evals/baselines/{classify,extract,answer}.json` are the v1 toy targets on the `test` split, offline, created with `evalgate run evals/suites/<suite>.yaml --split test --cache off --out evals/baselines/<suite>.json` against `toy-targets` on port 8110. New baselines are new files (append-only); rotation is in `docs/runbook.md`. | Baseline on `dev`. | The gate compares like with like: CI runs the `test` split. |
| 2026-10-16 | Python Playwright is pinned to 1.56.0. | Latest (1.64). | 1.56.0 matches the Chromium (1194) and ffmpeg (1011) builds preinstalled in `/opt/pw-browsers`; video capture needs the matching ffmpeg and `playwright install` is not allowed in the cloud container. |
| 2026-10-16 | Accessibility checks use `axe-playwright-python` (bundles axe-core, MPL-2.0). | Injecting axe-core from npm. | One Python dependency; the e2e container needs no Node. |
| 2026-10-16 | A report over 50 MB is never read: it appears in the viewer's error panel and in `/api/runs` errors with `status: 413`; the HTTP status of the page itself stays 200 so the other runs still show. | Fail the whole page with 413. | FR-8 asks for valid runs to show next to the bad file. |
| 2026-10-16 | The license check accepts Zlib, CC0-1.0 and CNRI-Python only as parts of an AND expression next to an allowed license (numpy and regex bundle such components). | Fail those packages. | They are permissive licenses of bundled components, not the package's own license. |
| 2026-10-16 | OTel export turns on with `--otel` or when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; the runner leaves telemetry alone when the embedding application already configured it. | Only `--otel`. | The OTel convention is that the endpoint variable enables export; resetting a host application's providers would drop its spans. |
| 2026-10-16 | The viewer rejects requests whose `Host` header is not loopback or listed in `EVALGATE_SERVE_ALLOWED_HOSTS` (421). Compose sets it to `report-viewer` for the e2e container. | Bind address only. | DNS rebinding can reach a loopback-bound server from a browser; the Host check closes it. |
| 2026-10-16 | PII redaction uses bounded quantifiers and redacts at most the first 200,000 characters of a prompt (the rest is cut). | Unbounded regexes. | The security review found super-linear backtracking on hostile input; bounded patterns are linear (`test_redaction_is_linear_on_hostile_input`). |
| 2026-10-16 | Generated `evals/reports/*.md` are gitignored like `*.json`. | Commit the Markdown reports. | They are regenerated by `make eval`; `evals/REPORT.md` is the committed summary. |
| 2026-10-16 | `compose.test.yaml` joins the main stack's network (`evalgate_default`, external) and runs real `wiremock/wiremock:3.13.1` on 8142/8143 with the same mappings as the in-process double. | A standalone test stack with its own viewer. | The e2e container must hit the seeded viewer, and contract tests must prove the mappings work in real WireMock. |
| 2026-10-16 | The e2e image is `mcr.microsoft.com/playwright/python:v1.56.0-noble` with `playwright==1.56.0` pinned in the same `pip install`. | Let `axe-playwright-python` pull the latest Playwright. | Without the pin pip installed Playwright 1.64, whose browsers are not in the 1.56 image (first `make test-docker` run: 5 e2e errors). |
| 2026-10-16 | CI workflows run on `pull_request` and on pushes to `main` only; `claude-review.yml` is not added. | Run on every branch push; add the optional review workflow. | Branch pushes are covered once a PR is open; the optional review workflow needs an `ANTHROPIC_API_KEY` secret this repository is not known to have. |
| 2026-10-16 | `make demo` gates the classify suite: v2 against the committed v1 baseline (exit 1), then v1 (exit 0); reports go to `.evalgate/demo/`. `EVALGATE` overrides the command so the test runs it with the test interpreter. | Demo through the viewer only. | FR-7 and FR-14 are about the gate's exit code; the classify drop (-16.67 pp, CI [-26.67, -8.33]) is the clearest example. |
| 2026-10-16 | markdownlint runs with MD013 (line length) and MD060 (table column style) off. | Hard-wrap prose at 80 or 120 columns. | Prose is one paragraph per line so diffs stay per paragraph; compact tables (`---` separators without padding) are the house style. Every other default rule is on. |
| 2026-10-16 | `scripts/check_coverage.py` enforces the §10 gates from coverage JSON: >= 85% per core package (suite, runner, targets, metrics, judge, stats, cache, store, report) and >= 70% overall. | `--cov-fail-under` (overall only). | pytest-cov has no per-package threshold. |
| 2026-10-16 | `make docs` exports the toy targets' OpenAPI document to `docs/contracts/openapi/toy-targets.json`; `make schemas` fails on its drift. The viewer has no OpenAPI document. | Hand-written API docs. | The FastAPI app is the source of truth; the stdlib viewer has only a few read-only JSON routes. |
| 2026-10-16 | Spans and JSON log lines inside a run carry `app.run_id` through a context variable set by the runner; judge spans add `gen_ai.response.model`, `gen_ai.usage.*` and `app.cost_usd`. | Pass the run id through every call. | The gateway and judge stay independent of the runner; asyncio tasks inherit the context. |
| 2026-10-16 | `GateFlapping` fires on `changes(evalgate_gate_last_decision[6h]) >= 3`, a 6-hour time window instead of the spec's "3 decision changes in 5 runs". | A count-based window over the last 5 runs. | PromQL cannot window a gauge by sample count; the runbook (#gate-flapping) explains when the two differ. |
| 2026-10-16 | Metrics are exported without a per-process `service.instance.id`; traces keep one. | One instance id on both (added in M6). | Per-process ids split `evalgate_gate_last_decision` into one series per run, so `changes()` could never fire; counter restarts across runs are handled by `increase()`. |
| 2026-10-16 | The toy targets count requests in a middleware, so 422, 404 and 500 responses reach `toy_requests_total`. | Counting inside the handlers. | Handler counting only saw 200 and handled 400s, so `ToyTargetErrorRate` could stay silent during an outage. |
