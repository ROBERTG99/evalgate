# Known limitations

What is not done, or done with a documented gap. Each entry names the reason.

- **Third-party LLM metrics bypass the gateway.** `ragas:` and `deepeval:` metrics that call an LLM use those libraries' own clients, so they skip evalgate's cache, PII redaction, `LIVE_EVAL_BUDGET_USD` and the offline socket guard. Use their non-LLM metrics in gates (ExactMatch, StringPresence, NonLLMStringSimilarity, BLEU/ROUGE; DeepEval ExactMatchMetric, PatternMatchMetric); the offline test suite only exercises those.
- **Release binaries are not checksum-verified.** `scripts/install_tools.sh` downloads hadolint, trivy and shellcheck over HTTPS from GitHub releases by pinned version but does not verify SHA-256 sums; actionlint and gitleaks are built from the Go module proxy, which is checksum-verified by `sum.golang.org`.
- **No recorded LLM cassettes.** No provider key was available during the build, so `tests/fixtures/llm/` holds no cassettes and the provider adapters are tested against response fixtures written in the documented API shapes (`tests/fixtures/provider_responses/`), not recordings.
- **Judge labels are by construction.** All 260 judge labels were generated with known answers; the maintainer review of 40 labels is pending (see `PROGRESS.md`). See ADR-0006 for what this does and does not prove.
- **`gate_audit` only covers `evalgate check` runs on the same machine.** CI keeps `runs.duckdb` as a 14-day artifact; there is no central audit store.
- **Percentile bootstrap under-covers at small n.** The §11 coverage check (400 simulated datasets of 150 correlated binary cases, 10,000 resamples) measures 0.96, but the same simulation gives about 0.89 for 60 cases with a near-perfect baseline (0.97 → 0.95) and about 0.84 for 20 cases (`evals/reports/bootstrap-coverage.json`, scenarios table in `evals/REPORT.md`). In those regimes a "statistically supported" regression is somewhat more likely to be a false alarm than the nominal 2.5% one-sided rate. Mitigations: the gate also requires the drop to exceed `--max-regression-pp`, needs at least 10 paired cases (`MIN_PAIRED`), and test splits should be larger than 60 when a metric sits near 1.0. A BCa or exact-binomial interval is the next improvement.
- **No multiple-comparison adjustment.** Each gated metric is tested on its own at 95%. With several gated metrics at the margin (extract gates 6), the chance that at least one shows a false regression is higher than for one metric ([design FAQ, question 2](design-faq.md#2-how-are-multiple-comparisons-handled)).
- **The meta-evaluation regressions are coarse.** The toy targets are deterministic and the injected regressions are large; most also fail an absolute threshold or a budget. 30/30 detected and 0/20 false alarms give exact 95% bounds of [0.884, 1.0] and [0, 0.168] (`evals/reports/meta-eval.json`), so the §11 targets are met as point estimates, not with certainty.
- **`.env.example` is also unreadable for Claude Code.** `.claude/settings.json` denies `Read(./.env.*)` to keep real environment files away from the agent; permission rules have no exceptions, so the committed `.env.example` is covered too. Read it with `cat` from a terminal, or narrow the rule to named files if that matters more than the blanket deny.
