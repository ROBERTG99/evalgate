# Evaluation

This page explains how evalgate evaluates itself: the suites it runs against three toy systems, the baselines it gates against, the meta-evaluation of the gate, judge calibration, the bootstrap coverage simulation, the performance benchmarks and the live evals. Every number below is copied from a report file named next to it. The JSON files under `evals/reports/` are gitignored and regenerated by the commands listed in [Reproducing each number](#reproducing-each-number); the committed summary [`evals/REPORT.md`](../evals/REPORT.md) is generated from them by `scripts/build_eval_report.py`. All numbers here are offline (FakeJudge, no provider calls) unless a row says otherwise.

All data is synthetic, produced by `data/generator/` version 1.0.0 with seed 1337 (`evals/datasets/MANIFEST.json`). Labels are known by construction; see [ADR-0006](adr/0006-labels-by-construction.md).

## Toy systems and suites

The toy targets (`examples/toy-targets/`, FastAPI, port 8110) imitate three small AI systems. `X-Toy-Version: v1` is the reference behaviour, `v2` is a deliberate regression, and `X-Toy-Variant: <id>` selects one of 50 catalogued mutations used by the meta-evaluation. Steps carry synthetic token counts priced as model `toy-model`.

Each suite runs over 150 rows (90 `dev`, 60 `test`); the gate and the baselines use the `test` split. Thresholds are the build spec §11 values and are only ever raised.

| Suite | System | Dataset | Gated metrics (kind, threshold) | Budget |
|---|---|---|---|---|
| [`classify.yaml`](../evals/suites/classify.yaml) | Support-ticket classification, `POST /classify` | `evals/datasets/toys/classify.v1.jsonl` | `label_accuracy` (exact, ≥ 0.90); `label_format` (regex, 1.0) is reported but not gated | USD 0.01, p95 800 ms |
| [`extract.yaml`](../evals/suites/extract.yaml) | Invoice field extraction, `POST /extract` | `evals/datasets/toys/extract.v1.jsonl` | `schema_valid` (json_schema, 1.0), `total_tolerance` (numeric_tolerance ±0.01, ≥ 0.95), `invoice_number_exact`, `date_exact`, `currency_exact`, `vendor_exact` (exact, ≥ 0.95 each) | USD 0.02, p95 800 ms |
| [`answer.yaml`](../evals/suites/answer.yaml) | FAQ answering with tools over a 40-document corpus, `POST /answer` | `evals/datasets/toys/answer.v1.jsonl` | `answer_contains` (contains_all, ≥ 0.85), `tool_calls` (tool_calls, ≥ 0.95), `answer_correctness` (judge, rubric `answer_correctness.v1`, ≥ 0.85) | USD 0.05, p95 800 ms |

## Baselines

The baselines in `evals/baselines/` are report.v1 files of the v1 targets on the `test` split, offline, created with `evalgate run evals/suites/<suite>.yaml --split test --cache off --out evals/baselines/<suite>.json` ([`DECISIONS.md`](DECISIONS.md)). They are append-only: a new baseline is a new file, as described in [`runbook.md`](runbook.md#baseline-rotation).

Against these baselines the current v1 runs show no change: every comparison has a delta of +0.00 pp with a 95% CI of [+0.00, +0.00] on 60 paired cases, 10,000 resamples, seed 1337, maximum regression 1.0 pp (`evals/reports/check-classify.json`, `evals/reports/check-extract.json`, `evals/reports/check-answer.json`). This is expected: the toy targets are deterministic.

## Meta-evaluation of the gate

The question is whether the gate catches real regressions without failing harmless changes. `scripts/meta_eval.py` (`make meta-eval`) runs each of the 50 catalogued variants in `evals/datasets/meta/variants.v1.jsonl` on its suite's `test` split through `X-Toy-Variant`, and checks the report against the v1 baseline with the production gate rule (10,000 resamples, seed 1337, `--max-regression-pp 1.0`, at least 10 paired cases). It exits 1 when detection is below 0.90 or the false-positive rate is above 0.10.

- 30 injected regressions: 24 quality mutations (for example a dropped classification rule, swapped labels, a day/month swap, a rounded total, a skipped `read_doc` call, an answer with numbers removed), 3 cost mutations (token inflation) and 3 latency mutations, 10 per system.
- 20 neutral changes that must pass: confidence jitter, small latency or token changes, renamed steps, an extra output field, reordered keys, a prompt version bump, a polite suffix and similar.

Results (`evals/reports/meta-eval.json`):

| Measure | Value | Exact 95% CI (Clopper-Pearson) |
|---|---:|---|
| Regressions detected | 30/30 (1.00) | [0.8843, 1.0] |
| Neutral changes failed | 0/20 (0.00) | [0.0, 0.1684] |

By system, each of classify, extract and answer detected 10/10 regressions; neutral changes failed 0/7, 0/7 and 0/6 respectively (`evals/reports/meta-eval.json`, `by.system`). Failure reasons across the detected regressions: `regression` 24, `threshold` 24, `budget_cost` 3, `budget_p95` 3 (`regressions_by_failure_reason`; one variant can have several reasons). The §11 targets (detection ≥ 0.90, false positives ≤ 0.10) are met as point estimates; the lower bound of the detection interval, 0.8843, is below 0.90, so they are not met with certainty.

## Judge calibration

A judge rubric is adopted only after it passes calibration on its `test` labels: agreement ≥ 0.80, Cohen's kappa ≥ 0.70, position inconsistency ≤ 0.10, verbosity bias ≤ 0.05 and zero injection pass-through. Prompt and rubric work iterates on the `dev` split (`evalgate calibrate --split dev`); `make calibrate` (`scripts/calibrate_all.py`) runs every rubric in `evals/rubrics/` once on `test` and exits 1 on any failure.

| Rubric | Mode, scale, route | Test labels | Agreement | Kappa | Position inconsistency | Verbosity bias | Injection pass-through | Source |
|---|---|---:|---:|---:|---:|---:|---|---|
| `answer_correctness.v1` | pointwise, binary, `judge` | 64 | 0.875 | 0.746 | 0.000 | +0.000 | 0.000 (8 items) | `evals/reports/calibration-answer_correctness.json` |
| `pairwise_preference.v1` | pairwise, `judge` | 16 | 0.875 | 0.812 | 0.000 | +0.000 | 0.000 (0 items) | `evals/reports/calibration-pairwise_preference.json` |
| `rubric_adherence.v1` | pointwise, likert5, `judge_hard` | 24 | 0.917 | 0.824 | 0.000 | +0.000 | 0.000 (0 items) | `evals/reports/calibration-rubric_adherence.json` |

The first two rubrics share `evals/datasets/judge/answer_correctness.labels.v1.jsonl` (200 items, 120 dev and 80 test; the 80 test items split into 64 pointwise and 16 pairwise). `rubric_adherence` uses its own 60-item `rubric_adherence.labels.v1.jsonl` with binary labels (adherent = rating 5). These numbers measure FakeJudge, the offline rule-based judge, against labels known by construction; they show the calibration pipeline works and that FakeJudge is a reasonable offline stand-in, not how a real model performs. The disagreements are listed per item in each calibration file (for example 3 `number_words` and 3 `negation` items for `answer_correctness`).

## Bootstrap coverage simulation

The gate's claim "the 95% CI of the delta excludes 0" is only as good as the interval's coverage. `src/evalgate/stats/simulation.py`, run by `make eval` (`scripts/run_evals.py`), draws 400 simulated paired datasets per scenario, with a latent per-case difficulty shared by both runs (correlation 0.6) and a known true delta, and counts how often the 95% paired percentile interval (10,000 resamples, seed 1337 plus the dataset index) contains it. Outcomes are binary except in `n60_continuous`, which uses graded scores in [0, 1]. The §11 target is coverage between 0.92 and 0.98 for the primary scenario.

| Scenario | Cases | Baseline → candidate parameter | True delta | Coverage | Mean CI width (pp) |
|---|---:|---|---:|---:|---:|
| `primary_n150_binary` | 150 | 0.85 → 0.80 | -5.00 pp | 0.9600 | 14.1286 |
| `n60_binary` | 60 | 0.85 → 0.80 | -5.00 pp | 0.9375 | 22.1462 |
| `n60_continuous` | 60 | 0.70 → 0.65 | -4.12 pp | 0.935 | 14.9728 |
| `n60_near_perfect` | 60 | 0.97 → 0.95 | -2.00 pp | 0.8875 | 11.1127 |
| `n20_binary` | 20 | 0.85 → 0.80 | -5.00 pp | 0.8425 | 36.0381 |

Source: `evals/reports/bootstrap-coverage.json`. The primary scenario meets the target; the small-n and near-perfect scenarios under-cover, which is why the gate also requires the drop to exceed `--max-regression-pp` and at least 10 paired cases. See [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md).

## Live evals

`make eval-live` (`scripts/eval_live.py`) calibrates `answer_correctness.v1` on its test labels with a real judge model (`EVALGATE_JUDGE_MODEL`, default `claude-haiku-5-5`). It needs a provider key, prints the cost estimate first, stops before any call when the estimate is above `LIVE_EVAL_BUDGET_USD` (default 2), and keeps a hard stop during the run. `make record-fixtures` runs the same script with `EVALGATE_RECORD_CASSETTES=1` to record cassettes.

Live evals were not run: no provider key was available. `evals/reports/live-eval.json` records `"ran": false` with reason `ANTHROPIC_API_KEY not set` (created 2026-10-16T19:47:26Z). Every number on this page is therefore offline, and `tests/fixtures/llm/` holds no recorded cassettes. Running it is listed for the maintainer in `PROGRESS.md`; see also [`runbook.md`](runbook.md#live-evals-and-budget).

## Reproducing each number

Start the toy targets (`docker compose up -d --wait`, or `uv run --frozen toy-targets --port 8110`); `scripts/meta_eval.py` and `scripts/run_evals.py` start them in-process when `EVALGATE_TOYS_URL` does not answer. No API key is needed.

| Command | Writes | Numbers on this page |
|---|---|---|
| `make eval` | `evals/reports/{classify,extract,answer}.json`, `check-*.json`, `bootstrap-coverage.json`, then runs `make calibrate` and `make meta-eval` and writes `evals/REPORT.md` | Suite results, baseline comparisons, coverage |
| `make calibrate` | `evals/reports/calibration-*.json` | Judge calibration |
| `make meta-eval` | `evals/reports/meta-eval.json` | Meta-evaluation |
| `make bench` | `evals/reports/bench.json` | Benchmarks |
| `make eval-live` | `evals/reports/live-eval.json` | Live evals |
| `make demo` | `.evalgate/demo/*.json`; transcript in `docs/demo-transcript.txt` | v2 classify regression |

Reports are reproducible: same inputs and seed give identical reports except `run_id`, `created_at` and latencies (NFR-9 in `evals/reports/bench.json`). In CI, `.github/workflows/evals.yml` gates each suite through `./action` and runs `make eval`, uploading `evals/reports/` and `evals/REPORT.md` as the `eval-reports` artifact for 14 days.

## Limits

- The toy targets are deterministic and the injected regressions are coarse; most also fail an absolute threshold or a budget, so the meta-evaluation shows the gate works on clear cases, not that it is sensitive to subtle ones.
- Judge labels are by construction and the maintainer review of 40 labels is pending; calibration numbers describe FakeJudge, not a live model.
- The percentile bootstrap under-covers at small n and near-perfect rates, and there is no multiple-comparison adjustment across gated metrics.
- No live numbers and no recorded cassettes exist yet.

The full list, with reasons and mitigations, is in [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md).
